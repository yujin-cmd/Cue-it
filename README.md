# 큐잇(Cue-it) — 설치 및 사용 안내

발표 중 막히면 다음 할 말을 알려주는 AI 큐카드입니다. 방송 현장의 FD처럼, 발표자에게만 보이는 신호(큐)를 줍니다.
발표자의 말을 실시간으로 따라가다가, 말이 막혀 「큐 주세요」를 누르면 이어서 할 말을 보여줍니다. 빠뜨린 핵심과 남은 시간도 함께 챙깁니다.

터미널 명령 없이 웹 화면 클릭만으로 배포합니다.

---

## A. 준비물

| 항목 | 용도 |
| --- | --- |
| GitHub 계정 | 코드 보관 |
| Netlify 계정 | 배포 (GitHub 계정으로 로그인 가능) |
| Anthropic API 키 | 발표 전 분석·예상 질문 생성 |
| Chrome 브라우저 | 음성 인식 (Edge도 가능, Safari·Firefox 불가) |

API 키는 console.anthropic.com → API Keys 에서 발급하고, 결제 수단을 등록해 크레딧을 넣어야 합니다.

---

## B. 배포 (10분)

### 1. GitHub에 저장소 만들기
1. github.com 로그인 → 오른쪽 위 **+** → **New repository**
2. Repository name: `cue-it`
3. **Public** 선택 → **Create repository**

### 2. 파일 올리기
1. 만들어진 저장소 화면에서 **uploading an existing file** 링크 클릭
2. 압축을 푼 `cue-it` 폴더를 **연 다음, 안에 있는 항목 전부**(netlify.toml, package.json, README.md, public 폴더, netlify 폴더)를 끌어다 놓습니다
   - 폴더 자체를 통째로 끌면 경로가 한 단계 깊어져 배포가 실패합니다. **폴더를 열고 그 안의 내용물**을 끌어야 합니다
3. 아래 **Commit changes** 클릭

### 3. Netlify에 연결
1. app.netlify.com 로그인 → **Add new site** → **Import an existing project**
2. **Deploy with GitHub** → 방금 만든 `cue-it` 선택
3. 설정은 그대로 두고 (Publish directory가 `public`인지만 확인) **Deploy**

### 4. API 키 넣기 ★ 이 단계를 빠뜨리면 분석이 실패합니다
1. 배포된 사이트 화면에서 **Site configuration** → **Environment variables**
2. **Add a variable** → **Add a single variable**
   - Key: `ANTHROPIC_API_KEY`
   - Value: 발급받은 API 키 (sk-ant-... 로 시작)
3. **Create variable**
4. **Deploys** 탭 → **Trigger deploy** → **Clear cache and deploy site**
   (환경변수는 새로 배포해야 반영됩니다)

### 5. 확인
사이트 주소로 접속해 화면이 뜨면 완료입니다. 주소는 **Site configuration → Change site name**에서 바꿀 수 있습니다.

## C. 사용법

### 0단계 · 체험하기 (자료 없이 먼저 보기)
사이트에 들어가면 큐잇 로고가 약 3초 동안 그려진 뒤 첫 화면이 열립니다. 화면을 누르거나 아무 키나 누르면 바로 넘어갑니다.
첫 화면의 **▶ 3분 자동 시연**을 누르면, 가상의 공모전 발표 「동네 공유 우산」으로 준비 → 검토 → 연습 → 발표 → 리포트 → 질의응답 여섯 단계를 차례로 보여줍니다.
화면 위쪽의 노란 안내 문구가 지금 무엇을 보여주는지 설명하고, 설명하는 곳에 테두리가 표시됩니다.
안내 문구의 **잠깐 멈춤**으로 멈춰 읽을 수 있고, **다음 단계**로 지금 단계를 건너뛸 수 있습니다.
마이크·파일·API 키가 없어도 되고, 음성 인식이 안 되는 브라우저(Safari 등)에서도 동작합니다.
**샘플로 직접 해보기**를 누르면 같은 샘플로 검토·연습·발표를 직접 해 볼 수 있습니다.

- 자동 시연은 AI를 부르지 않습니다(미리 분석해 둔 결과 사용). 연습 장면의 꼬리질문, 리포트의 AI 코칭, 질의응답에서 AI가 찾은 슬라이드도 샘플 발표로 미리 받아 둔 결과입니다. 단, **샘플로 직접 해보기**에서 연습 질문에 직접 답하면 꼬리질문은 AI가 만듭니다.
- 자동 시연의 준비 장면은 유형을 고르고 파일을 넣는 모습을 보여주기만 합니다. 장면이 끝나면 내가 고른 유형, 넣어 둔 파일, 써 둔 대본이 그대로 돌아옵니다.
- 체험 중에는 내 자료와 리포트 기록이 바뀌지 않습니다. **체험 끝내기**를 누르면 원래 상태로 돌아옵니다.
- 사이트 주소 끝에 `?demo=auto`를 붙이면 접속하자마자 자동 시연이 시작됩니다. (예: `https://내사이트.netlify.app/?demo=auto`)
  `?demo=try`는 샘플 자료를 바로 엽니다.
- 샘플 내용은 `public/demo/demo.js`와 `public/demo/sample.pdf`에 있습니다.

### 1단계 · 준비
0. **발표 유형**을 고릅니다. 유형에 따라 기본 시간, 꼭 전달할 내용, 질문하는 사람이 바뀝니다

   | 유형 | 기본 시간 | 꼭 전달할 내용 | 질문하는 사람 |
   | --- | --- | --- | --- |
   | 면접 발표 | 5분 | 지원 동기, 핵심 강점, 경험 사례, 입사 후 포부 | 면접관 |
   | 업무 보고 | 10분 | 결론, 근거, 필요한 결정, 일정 | 상사 |
   | 수업·과제 발표 | 7분 | 주제, 방법, 결과, 한계 | 교수님 |
   | 공모전·투자 발표 | 5분 | 문제, 해결책, 차별점, 실현 계획 | 심사위원 |
   | 자유 형식 | 7분 | AI가 자료에서 찾음 | 청중 |

1. PowerPoint에서 **파일 → 다른 이름으로 저장 → PDF**로 저장합니다
2. 그 PDF를 업로드하고, 발표 대본을 붙여넣습니다 (대본이 없으면 비워도 됩니다 — AI가 만듭니다)
3. **분석 시작** → 30초쯤 걸립니다

### 2단계 · 검토
AI가 뽑은 핵심 항목을 확인합니다. **필수** 항목을 말하지 않고 슬라이드를 넘기면 큐가 뜹니다.
고른 유형에서 꼭 전달할 내용이 자료에 빠져 있으면 화면 위쪽에 알려줍니다(AI의 참고 의견이므로 이미 넣었다면 넘어가도 됩니다).
문구를 고치거나 필요 없는 항목은 지우십시오. 이 단계를 건너뛰지 마십시오 — 항목의 품질이 실전 정확도를 결정합니다.

### 3단계 · 연습
난이도를 고르고 질문에 답하면 꼬리질문이 이어집니다. 질문하는 사람은 발표 유형에 따라 면접관·상사·교수님·심사위원으로 바뀝니다. 답변을 대신 만들어 주지 않습니다.

### 4단계 · 발표
**발표 시작을 누르면 화면 전체가 어두워집니다.** 강의실 조명이 꺼진 상태에서 밝은 화면은
발표자 얼굴을 하얗게 뜨게 만들기 때문입니다. 발표를 종료하면 원래 밝은 화면으로 돌아옵니다.

1. 목표 시간을 입력합니다
2. **슬라이드 창 열기** → 열린 창을 프로젝터 화면으로 옮기고 **F11**로 전체화면
3. 이 창(발표자 화면)은 노트북에 둡니다
4. **발표 시작** → 마이크 권한을 허용합니다
5. 방향키 또는 프레젠터 리모컨으로 넘깁니다. 리모컨은 키보드 신호를 보내므로 그대로 동작합니다
6. **B** 또는 **마침표(.)** 키가 「큐 주세요」입니다. 말이 막혔을 때 누르면, 지금까지 한 말을 따라가서 바로 다음에 이어질 문장과 핵심 단어를 화면 가득 보여줍니다
7. 시간이 부족해지면 화면에 **건너뛰기 버튼**이 나타납니다. 어느 슬라이드를 건너뛰고 어디로 가는지 버튼에 적혀 있으며, 누르면 필수 항목이 남은 다음 슬라이드로 바로 이동합니다

### 6단계 · 질의응답
질문을 텍스트로 입력하거나 🎤 버튼으로 받아 적으면, 두 단계로 관련 슬라이드를 찾아줍니다.
먼저 질문과 같은 낱말이 있는 슬라이드를 기다림 없이 바로 보여 주고, 1~3초 뒤 **AI가 질문의 뜻을 읽어** 더 맞는 슬라이드를 앞에 올립니다. "돌려주지 않으면"처럼 슬라이드의 낱말("반납")과 다르게 물어도 찾습니다.
AI에는 질문과 슬라이드 요약(제목·핵심·대본 문장)만 보냅니다. AI 호출이 실패해도 낱말로 찾은 결과는 그대로 남고, 자료에 근거가 없으면 없다고 알려줍니다.
「이 슬라이드 띄우기」를 누르면 슬라이드 창이 그 장으로 바로 이동합니다. 답변은 만들어 주지 않습니다.

### 5단계 · 리포트
놓친 필수 핵심, 목표 대비 실제 시간, 슬라이드별 소요, 「큐 주세요」 횟수, 건너뛴 슬라이드가 남습니다.
최근 10회가 보관되므로 1차 연습과 5차 연습을 나란히 비교할 수 있습니다.

방금 마친 발표에는 **AI 코칭 받기** 버튼이 나옵니다. 누르면 AI가 발표 기록(놓친 핵심, 시간, 큐 요청 횟수 등)을 읽고 잘한 점, 다음에 고칠 점, 다음 연습에서 해볼 한 가지를 알려줍니다.
버튼을 누를 때만 기록이 AI로 전송되며, 점수를 매기거나 발표 문장을 대신 써 주지 않습니다.

## E. 자주 막히는 곳

| 증상 | 원인과 해결 |
| --- | --- |
| 분석이 "AI 분석 실패"로 끝남 | 환경변수 미설정 또는 재배포 안 함. B-4를 다시 확인 |
| 음성이 전혀 인식되지 않음 | Chrome이 아니거나 마이크 권한 거부. 주소창 왼쪽 자물쇠 → 사이트 설정에서 마이크 허용 |
| 슬라이드 창이 비어 있음 | 같은 브라우저의 같은 사이트에서 열어야 합니다. PDF를 먼저 업로드했는지 확인 |
| 말했는데 체크가 안 됨 | 2단계에서 항목 문구를 실제 말하는 표현에 가깝게 고치십시오 |
| 발표 도중 인식이 멈춤 | 자동 재시작이 들어 있으나, 마이크를 다른 프로그램(Zoom 등)이 점유하면 끊깁니다 |
| 분석이 중간에 멈춤 | 슬라이드를 한 장씩 나눠 분석하므로 장수가 많으면 시간이 걸립니다. 버튼에 표시되는 진행 숫자가 올라가면 정상입니다 |
| 함수 실행 시간이 초과되었다는 메시지 | 잠시 후 다시 시도하십시오. 특정 슬라이드에서 반복되면 그 슬라이드의 텍스트가 지나치게 긴 경우입니다 |

## F. 구조

```
cue-it/
├─ netlify.toml              배포 설정 (/api/* → 함수 연결)
├─ package.json
├─ public/
│  ├─ index.html             발표자 화면 (5단계 전부)
│  ├─ slides.html            프로젝터용 슬라이드 창
│  ├─ style.css
│  ├─ app.js                 전체 흐름 제어
│  ├─ match.js               ★ 핵심 전달 판정 (서버 호출 없음)
│  │                          질의응답 관련 슬라이드 검색도 같은 엔진 사용
│  ├─ presets.js             ★ 발표 유형 정의 (화면과 서버 함수가 함께 사용)
│  ├─ store.js               로컬 저장 (PDF·분석결과·리포트)
│  └─ demo/                  체험하기용 샘플 (demo.js 분석 결과·시연 대본, sample.pdf 슬라이드)
└─ netlify/functions/
   ├─ analyze.mjs            발표 전 분석·예상 질문·자료에 빠진 내용 확인·발표 후 AI 코칭·질의응답 슬라이드 찾기 (Anthropic API)
   └─ qa.mjs                 연습 중 꼬리질문
```

**발표 중에는 AI 서버를 호출하지 않습니다.** 핵심 판정은 `match.js`가 브라우저 안에서 처리합니다.
다만 음성을 글자로 바꾸는 일은 브라우저(Chrome)의 음성 인식이 맡는데, 이 기능은 인터넷 연결이 필요할 수 있습니다.
발표 자료 원본(PDF)은 서버로 전송되지 않고 브라우저에만 저장됩니다(분석 단계에서 슬라이드 글자만 전송).
AI가 하는 일은 발표 전(핵심 뽑기·예상 질문·빠진 내용 확인), 연습(꼬리질문), 발표 후(코칭), 질의응답(질문의 뜻에 맞는 슬라이드 찾기) 네 군데이며, 결과는 틀릴 수 있으므로 검토 단계에서 사람이 확인합니다.
